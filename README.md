# MAPTest2

MAPTest2 is a Java/Maven project that implements a small toy-language interpreter. It was built for MAP coursework and includes both a console menu and a JavaFX GUI for selecting and stepping through sample programs.

The interpreter supports typed variables, arithmetic and logical expressions, conditionals, loops, file reads, heap allocation, heap reads/writes, forked program states, and barrier synchronization.

## What is in this repository

```text
.
|-- pom.xml                         Maven build configuration
|-- mvnw, mvnw.cmd                  Maven wrapper scripts
|-- src/main/java
|   |-- com/example/maptest2        JavaFX application/controllers
|   |-- controller                  Interpreter execution controller
|   |-- model
|   |   |-- expresion               Expression AST nodes
|   |   |-- prgState                Runtime state structures
|   |   |-- statement               Statement AST nodes
|   |   `-- value                   Runtime values and types
|   |-- repository                  Program-state repository and logging
|   `-- view                        Console menu entry point
|-- src/main/resources/com/example/maptest2
|   |-- select-view.fxml            Program selection GUI
|   `-- main-window.fxml            Step-by-step interpreter GUI
`-- log*.txt                        Runtime logs generated by sample programs
```

## Requirements

- JDK 25, because `pom.xml` currently sets both Maven compiler `source` and `target` to `25`.
- Maven is not required globally if you use the included wrapper:
  - Windows: `.\mvnw.cmd`
  - macOS/Linux: `./mvnw`
- JavaFX dependencies are pulled by Maven from the dependencies listed in `pom.xml`.

If you are using IntelliJ IDEA, open the project as a Maven project and make sure the selected project SDK is JDK 25 or newer.

## Running the project

### JavaFX interpreter GUI

The Maven JavaFX plugin is configured to launch the full interpreter GUI:

```powershell
.\mvnw.cmd clean javafx:run
```

On macOS/Linux:

```bash
./mvnw clean javafx:run
```

This opens the program selector. You can also run `com.example.maptest2.MainGUI` directly from your IDE.

After selecting a sample program, the main window lets you execute one interpreter step at a time and inspect:

- number of active program states
- heap table
- output list
- file table
- program-state IDs
- symbol table for the selected state
- execution stack for the selected state

### Console interpreter

There are console menu entry points in:

```text
view.Main
com.example.maptest2.Main
```

Run either from the IDE to get a text menu of hard-coded sample programs. Choose a number to execute a program and `0` to exit.

## Sample programs

The GUI and console entry points define sample programs directly in Java. They demonstrate:

- simple variable declaration, assignment, and printing
- arithmetic expressions
- boolean conditionals
- type-checking failures
- file opening, reading, and closing
- relational expressions
- heap allocation with `new`
- heap reads with `rH`
- heap writes with `wH`
- garbage collection of unreachable heap addresses
- `while` loops
- `fork` for concurrent program states
- barriers with `newBarrier` and `await`

The project does not currently include a parser for a source language. Programs are constructed manually as AST objects using classes such as `CompStmt`, `VarDeclStmt`, `AssignStmt`, `PrintStmt`, `IfStmt`, `WhileStmt`, `ForkStmt`, `NewStmt`, and expression/value classes.

## How execution works

At a high level:

1. An `IStmt` tree describes a program.
2. The statement is type-checked before execution.
3. A `PrgState` is created with an execution stack, symbol table, output list, file table, heap, and barrier table.
4. A `Repository` stores active program states and writes log files.
5. The `Controller` executes one step for every active program state.
6. Forked statements create additional `PrgState` instances.
7. Before each multi-program step, reachable heap addresses are computed and unreachable heap entries are removed.

Concurrency is handled with a fixed thread pool in `Controller`.

## Important files

- `src/main/java/model/statement/IStmt.java`: common interface for statements.
- `src/main/java/model/expresion/Exp.java`: common interface for expressions.
- `src/main/java/model/value/type/Type.java`: type interface used during type-checking.
- `src/main/java/model/prgState/PrgState.java`: runtime state for a program.
- `src/main/java/controller/Controller.java`: drives one-step and all-step execution.
- `src/main/java/repository/Repository.java`: stores program states and logs execution.
- `src/main/java/com/example/maptest2/MainGUI.java`: JavaFX program-selection app.
- `src/main/java/com/example/maptest2/MainWindowController.java`: JavaFX execution window controller.
- `src/main/java/view/Main.java`: console app with sample programs.

## Logs and generated files

Running programs creates or updates files such as:

```text
log1.txt
log2.txt
...
log12.txt
```

These logs contain snapshots of program states during execution and are useful for debugging interpreter behavior.

The `target/` directory is generated by Maven and should not be edited by hand.

## Current caveats

- Example programs are duplicated across the GUI and console entry points.
- Program 4 intentionally contains a type error, but its type-check call is commented out in the entry points.
- Some file-reading examples use hard-coded paths such as `src/main/java/test.in` or `src/test.in`; run from the project root so relative paths resolve correctly.
- There are JUnit dependencies in `pom.xml`, but no dedicated test suite is currently present.
- Several packages/classes contain coursework-era spelling or naming inconsistencies, for example `expresion` instead of `expression`.

## Extending the interpreter

To add a new language feature, you will usually need to:

1. Add or update a value/type class under `model/value` or `model/value/type`.
2. Add an expression or statement implementation under `model/expresion` or `model/statement`.
3. Implement both runtime execution and static type-checking behavior.
4. Add a sample program in `MainGUI` and/or the console `Main`.
5. Run the program and inspect the console output, GUI state tables, and generated logs.

For small experiments, the fastest path is to create a new hard-coded `IStmt` sample in one of the entry-point classes.
